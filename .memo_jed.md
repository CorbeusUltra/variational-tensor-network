# Mémo — lancer une simulation sur Jed

**Ordre : régler le script Python → transférer → soumettre → suivre → récupérer.**

## Prérequis sur Jed

- Un environnement Python **Linux CPU** installé dans `.venv`.
- Un fichier `run.slurm` à la racine du repo, configuré avec le compte `master`, la partition `academic` et la QoS `academic`.
- Dans ce fichier : sortie `outputs/logs/%j.log`, exécution avec `python -u` et `MPLBACKEND=Agg`.
- Pour les plots : conserver `output_path` et utiliser `show=False`.

**La création de l’environnement Linux et du fichier `run.slurm` reste à effectuer si elle n’a pas été faite depuis la rédaction de ce mémo.**

Les calculs se lancent via Slurm sur un nœud de calcul, jamais directement sur le Mac ni sur le nœud de connexion `jed2`.

## 1. Sur le Mac : transférer le code

Régler d’abord le modèle, les pavages, `D_values`, `chi_values_by_D` et le `schedule` dans `scripts/su_ctmrg_convergence.py`.

```bash
rsync -av \
  --exclude='.venv/' \
  --exclude='.git/' \
  --exclude='outputs/' \
  --exclude='__pycache__/' \
  "/Users/lucas/Documents/cesure/stage1/recherche/code/variational-tensor-network/" \
  lbourret@jed.hpc.epfl.ch:~/variational-tensor-network/
```

Ne pas retransférer le code pendant qu’un job l’utilise. Cette copie contient les modifications locales non commitées ; elle ne contient pas l’historique Git.

## 2. Depuis le Mac : se connecter

```bash
ssh lbourret@jed.hpc.epfl.ch
```

Depuis l’extérieur de l’EPFL, le VPN peut être nécessaire.

## 3. Sur Jed : soumettre le job

```bash
cd ~/variational-tensor-network
mkdir -p outputs/logs
sbatch run.slurm
```

Noter le numéro renvoyé et remplacer `123456` ci-dessous par ce numéro.

## 4. Sur Jed : suivre ou annuler

Voir les jobs en attente ou en cours :

```bash
squeue --me
```

Suivre le log en direct :

```bash
tail -f outputs/logs/123456.log
```

**Ctrl+C quitte seulement le suivi du log, sans arrêter le job.**

Après la fin, consulter l’état, la durée et le pic mémoire (parfois indiqué sur la ligne d’une étape du job) :

```bash
sacct -j 123456 --format=JobID,State,Elapsed,MaxRSS
```

Annuler volontairement un job :

```bash
scancel 123456
```

Le job continue après fermeture de la connexion SSH. Un log sans erreur ne suffit pas à valider la convergence : lire les warnings et les résultats.

## 5. Sur le Mac : récupérer les résultats

Dans un terminal local, pas dans la session SSH :

```bash
rsync -av \
  lbourret@jed.hpc.epfl.ch:~/variational-tensor-network/outputs/ \
  "/Users/lucas/Downloads/vtn-jed-results/"
```

Les PDF et logs restent également sur Jed. Les noms de PDF actuels étant fixes, un nouveau run peut remplacer les figures du précédent.

## Options à retenir

- `rsync -a` : copie récursive en conservant notamment dates et permissions ; `-v` : affiche les fichiers transférés.
- `mkdir -p` : crée les dossiers parents et accepte les dossiers déjà présents.
- `squeue --me` équivaut à `squeue -u lbourret`.
- Les commandes `sbatch`, `squeue`, `srun`, `scancel` appartiennent à **Slurm**.
- `.slurm` et `.sh` fonctionnent avec `sbatch` ; `.slurm` indique le rôle du fichier.
